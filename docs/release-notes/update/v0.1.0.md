# update v0.1.0

The first release of `update`, which checks for and applies updates to a command-line tool from
its GitHub releases. It requires `go.vipengele.org/cli/spec`, `cli/state`, `commons` and `filelock`,
each at v0.1.0.

- `update`: a tool describes itself with a `Config`. Every way it reaches the outside world (HTTP,
  the clock, the platform, the executable, the environment) is a field a test can substitute.
  - `Config.Start` checks for a newer release in the background, throttled by `CheckInterval` and
    skipped in CI or without a terminal. `Check.Notice` names the newer release without blocking.
  - `Config.Apply` runs the whole update: refuse an externally managed or unwritable executable
    and a downgrade below the highest version applied, download, verify, extract, preflight the
    staged binary (`Preflight` hooks included), and install. The install replaces the executable
    with two renames and keeps a backup until `Installed.Discard` or `Installed.Rollback`.
  - Downloads are bounded, checked against the release's SHA-256 checksums file, and, with
    `TrustedKeys`, accepted only once that file's minisign signature verifies.
  - `GitHubSource` reads the latest-release redirect and then the REST API, authenticated with
    `GH_TOKEN` or `GITHUB_TOKEN`, caches responses by ETag, and reports rate limits and rejected
    tokens as typed errors.
- `updatecmd`: the `update` command, as a `spec.Command` a tool adds to its `cli/core` `App`.
- `installscript`: renders a tool's POSIX-sh and PowerShell install scripts from its `Config`.
- `goreleaser`: renders the GoReleaser config that publishes releases in the form `Config` reads,
  used by the reusable `release-tool.yml` workflow.
- `asset`: names a release's archive and checksums files from a template.
- `updatetest`: a fake signed release and an HTTP server serving it as GitHub does, for tests.

Supported on Linux, macOS and Windows.

A consumer adds it with `go get go.vipengele.org/update@v0.1.0`.
