# config v0.1.0

The first release of `config`, which loads a program's configuration from layered providers into a
struct. It requires no sibling project.

- `Load(defaults, providers...)` binds the struct, whose fields are the keys and whose values are
  the defaults. `File` (YAML), `Env` (a prefix and a lookup function, such as `os.LookupEnv`) and
  `Flags` (the flags set explicitly) are the providers; the last one to set a key wins, and any
  type implementing `Provider` is a layer of its own.
- Keys are dotted snake_case paths taken from field names or `config:"name"` tags and matched
  relaxed, so `max-retries`, `MAX_RETRIES` and `maxRetries` name the same key. `File` and `Flags`
  reject an unknown key; `Env` looks up only the variables derived from the schema.
- `Result` carries, for every key, a `Source` naming its effective value and origin, such as
  `config.yaml:12` or `env APP_SERVER_MAX_RETRIES`.
- A type implementing `Validator` is validated after binding, with a `*FieldError` naming a key;
  a `RemovedKeys()` method reports a removed key with a hint instead of as unknown.
- `Seed` writes a commented default file, with `doc:"..."` tags as comments, and never replaces an
  existing one. `NewSchema` exposes the keys and their documentation; a schema problem matches
  `ErrSchema`.

A consumer adds it with `go get go.vipengele.org/config@v0.1.0`.
