# cli/core v0.1.0

The first release of `cli/core`, which runs command-line tools described with
`go.vipengele.org/cli/spec`. It requires `cli/spec`, `cli/state`, `config` and `commons`, each at
v0.1.0.

- `cli`: a tool builds an `App` with `New(identity, options...)`, adds its `spec.Command` trees
  and runs them with `App.Execute`, which returns the exit code. `Execute` and `ExecuteArgs` run a
  root command the tool builds itself.
  - Every App holds the `version` command, which answers `version --json` with the contract of the
    `buildinfo` package. `WithBuildInfo` overrides
    the build information it prints.
  - Standard flags are opt-in: `WithVerbose`, `WithQuiet`, `WithNoColor`, and either `WithJSON`
    (`--json`) or `WithOutput` (`--output text|json`).
  - `WithPreRun` and `WithPostRun` run hooks around every command.
  - Errors map to exit codes through `WithExitCode` and `WithExitCodeAs`, and render through
    `WithErrorRenderer`.
  - `WithConfig` loads a configuration struct through `go.vipengele.org/config` and adds the
    `config` command group. `WithLogging` adds `--log-level` and `--log-format` and installs a
    redacting `slog` logger, extended with `WithRedaction`. `WithCompletion` adds shell
    completion.
- `buildinfo`: the version, commit, build date, toolchain and platform of the running binary.
- `command/version`, `command/config`: the `version` command and the `config` command group, which
  locates, checks, shows and edits a tool's configuration file.
- `logging`: builds the process-wide `slog.Logger` from a level and format and redacts secrets;
  `logging/logtest` captures records for tests.

Commands are framework-neutral `spec.Command` values; the framework that parses the command line
is internal and is not part of the API.

A consumer adds it with `go get go.vipengele.org/cli/core@v0.1.0`.
