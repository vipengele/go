# cli/core v0.3.0

A paths layout option, command aliases and flag groups. It requires `cli/spec` at v0.2.0, released
with it, `config` at v0.2.0 and `cli/state` at v0.1.0.

- **`WithPathsLayout(paths.Layout)`** chooses the paths layout (ADR-0039) for every directory the
  App resolves, today the configuration directory, on any operating system. An unknown layout makes
  the command tree invalid, exit code 1. **`PathsLayoutFrom(ctx)`** returns the layout of the
  running App, `paths.LayoutDefault` outside one, to a hook or run function that resolves a
  directory of its own.
- **Aliases.** A command runs by any of its `spec.Command.Aliases`, and its help has an `Aliases:`
  line. Completion does not offer an alias as a candidate but resolves it when completing the
  arguments that follow. An alias `completion` on a child of the root is an invalid command tree
  under `WithCompletion`.
- **Flag groups.** The `FlagGroups` of a command are enforced as usage errors, exit code 2, before
  the `Output` resolver and the pre-run hooks run. The messages are `--a and --b are mutually
  exclusive` and `--a requires --b`.
- **Dependencies.** `cli/spec` is raised from v0.1.0 to v0.2.0 and `github.com/spf13/pflag` from
  v1.0.10 to v1.1.0, and the indirect `go.yaml.in/yaml/v3` from v3.0.5 to v3.0.6,
  `golang.org/x/mod` from v0.42.0 to v0.43.0, `golang.org/x/sys` from v0.49.0 to v0.50.0 and
  `golang.org/x/term` from v0.47.0 to v0.48.0. With pflag v1.1.0 an invalid integer flag value is
  reported as `must be an integer`.

A consumer upgrades with `go get go.vipengele.org/cli/core@v0.3.0`. Nothing has to change: a tool
that sets no layout resolves the directories of the operating system it runs on.
