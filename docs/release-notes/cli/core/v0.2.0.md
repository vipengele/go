# cli/core v0.2.0

A second configuration file, the overlay, and `config` commands that name every layer. It requires
`config` at v0.2.0, released with it, and `cli/spec`, `cli/state` and `commons` at v0.1.0.

- **`WithConfigOverlay(resolve, allow...)`** gives the configuration of `WithConfig` an overlay
  file, such as a project's own file, loaded above the user's `config.yaml` and below the
  environment variables. `resolve` receives the environment lookup and returns the overlay's path
  on every execution; an empty path or a missing file adds no layer, and a resolver error or any
  other error reading the file stops the run. The overlay may set only the keys in `allow`, as
  `config.File(path).Allow` checks them: any other key is an error at its line. With no keys it
  may set every key. An App has one overlay, and the last call decides; without `WithConfig` the
  command tree is invalid.
- **`config show`** starts with a header naming each layer, `defaults`, `file`, `overlay` when
  there is one and `env`, with its path or prefix, before the table of keys. `show --json` keeps
  `path` and adds `layers`, a list of `{name, path}`.
- **`config validate`** checks the defaults, the user file and the overlay together, without the
  environment, and lists every file it covered. With an overlay, an error names both files.
- `config edit` and `config path` work on the user file only, so `edit` cannot see a problem that
  appears only once the overlay is merged; `config validate` reports it.
- A configuration struct may hold maps and lists of structs, as `config` v0.2.0 accepts.

A consumer upgrades with `go get go.vipengele.org/cli/core@v0.2.0`. A tool that parses the text of
`config show` reads a layer header and a blank line before the table; the JSON form only gains a
key. Nothing else has to change.
