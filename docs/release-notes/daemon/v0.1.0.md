# daemon v0.1.0

The first release of `daemon`, which runs a tool's long-running work as a service. It requires
`go.vipengele.org/cli/spec`, `cli/state`, `filelock` and `update`, each at v0.1.0.

- `daemon`: a `Supervisor`, built with `New`, starts its `Runner`s in order and stops them in
  reverse within one shared grace period (`WithStartTimeout`, `WithGrace`, `WithOrder`).
  - `NewHTTPServer` and `NewHTTPServerListener` serve an `*http.Server` as a Runner.
  - `NewHealth` registers liveness and readiness checks and serves their `Snapshot`.
  - `WithInstanceLock` and `AcquireInstance` keep a second instance from running.
  - `WithReload` reloads configuration on SIGHUP and offers it to each `Reloader`.
  - `WithPanicPolicy` decides whether a panicking Runner stops the process or is isolated.
  - `WithSystemd` and `WithWindowsService` report readiness to the service manager.
  - A Runner requests a restart by returning an error wrapping `ErrRestartRequired`;
    `RestartRequested` tells a consumer to exit 0 so the service manager restarts it cleanly.
  - `WithUpdateGuard` and `WithUpdateReporter` connect self-update to the Supervisor and its
    status.
- `daemoncmd`: the commands a tool adds to manage its daemon: `NewService` with install,
  uninstall, start, stop, restart and status (`NewInstall`, `NewUninstall`, `NewStart`, `NewStop`,
  `NewRestart`, `NewServiceStatus`); `NewStatus` for the daemon's health; and `NewUpdate` and
  `NewUpdateStatus` for self-update.
- `selfupdate`: a `Machine` that records an update of the daemon's own binary before the swap,
  restarts into it, and rolls back an update the new build cannot confirm.
- `service`: installs and controls the service through systemd on Linux, launchd on macOS and the
  service control manager on Windows, selected at runtime. Service management and self-update are
  disabled inside a container.
- `httpserver`: the hardened `*http.Server` a daemon serves its API with.
- `systemd`: readiness and watchdog notification and socket activation, on the standard library
  only.
- `daemontest`, `servicetest`: test kits for code built on `daemon`; `servicetest` drives a Linux
  service under a real systemd in a podman container.

A consumer adds it with `go get go.vipengele.org/daemon@v0.1.0`.
