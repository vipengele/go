# filelock v0.1.0

The first release of `filelock`, an exclusive lock on a file that the operating system releases
when the holder closes the file or exits. It requires no sibling project.

- `New(path)` returns a `Locker`. `Lock(ctx)` waits until it holds the lock or the context is done
  and returns the function that releases it; `TryLock()` makes one attempt, and its error wraps
  `ErrLocked` when another descriptor holds the lock.
- `NewNoop()` returns a `Locker` that grants every lock at once and touches no file.
- Every lock opens its own descriptor, so two lockers in one process exclude each other as two
  processes do. The lock file is created at 0600 and never removed; a file left by an exited
  process never blocks a new one.
- The lock is `flock` on Linux, macOS and the BSDs and `LockFileEx` on Windows; elsewhere every
  attempt fails with an error wrapping `ErrUnsupported`.

A consumer adds it with `go get go.vipengele.org/filelock@v0.1.0`.
